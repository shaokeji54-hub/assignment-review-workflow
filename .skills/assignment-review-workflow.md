# 作业重审技能 v1.1.0

**Skill Name:** 作业重审 (Assignment Re-review)  
**Description:** 将个人过去的学术作业在多年后用AI重新审视，通过多轮迭代产出更成熟的新作品。核心价值在于时间的纵深——对比当年的自己和今天的自己。

## 何时使用

- 用户有过去（数年）的学术作业想要重做
- 用户希望系统地对比"当年写的"和"今天能写出的"
- 用户想要借助AI进行多维度拓展和迭代

## v1.1 新增核心改进

### 改进1：文件分类器

工作流入口处增加文件分类步骤。根据文件类型分叉处理管线，避免一刀切：

```
源文件 → 分类器
  ├── 议论文/分析类（思政作文、读后感、案例分析）
  │   → 完整流程：分析 + 重写 + 迭代
  ├── 工程课程设计类（除尘设计、水控设计、固废设计）
  │   → 脱敏 → 技术审校（替代分析笔记）→ 设计校核（替代重写）
  ├── 实验/检测报告类（微生物实验、土壤检测）
  │   → 脱敏 → 方法学评价 + 数据审校
  ├── 模板/空白类（合同模板、格式要求、课件）
  │   → 标记"模板" → 仅脱敏存档
  └── 扫描件/不可读类
      → 标记"需OCR" → 存档待处理
```

**分类依据**：读取文件前3段或前页内容，根据段落风格、专业术语密度、有无数据表格/公式判断。

### 改进2：版本质量锚点

每个版本设定最低验收标准，防止AI在批量操作中主动降级质量：

| 版本 | 最低要求 |
|------|---------|
| v1 | 脱敏完成 + 原文结构摘要 + 初步PII标注 |
| v2 | 分析笔记≥800字 + 新作品A≥1500字 + 至少3条具体引用/证据 |
| v3 | 所有事实陈述有出处 + 论证链条完整（有因果分析，非仅并列） |
| v4 | 至少1个有信息增量（非装饰性）的图表或可视化 |

锚点是硬性约束，不是参考值。AI在批量操作中不得主动降级。

### 改进3：处理模式选择

任务启动时要求用户明确模式：

```
请选择处理模式：
  1. 全量覆盖 — 每篇v1骨架，后续选篇深化（适合预览全貌）
  2. 精选深度 — 选3-5篇做到v2+，其余仅脱敏（适合快速产出高质量作品）
  3. 混合批次 — 按类别分批，每批3-5篇深化完再进下一批
```

模式一经选定，整批任务按该模式执行，中途不切换。

### 改进4：可视化作为可选项（非独立轮次）

图表不作为独立版本轮次，而是v2阶段的可选模块。AI应在分析笔记末尾加入"可视化建议"字段：

```
可视化建议：
  - 类型：流程图 / 象限图 / 时间线 / 对比图 / 决策树
  - 判断标准：图表能否揭示文字无法直观呈现的结构关系？
  - 不适合的场景：只有一个并列框的线性列表、纯文本流程
```

只有判断为"适合"时才生成图表，不做强制。

### 改进5：小组作业脱敏规则

新增多人协作场景的脱敏规则：

- 小组作业中的多名成员分配姓名A/姓名B/姓名C……体系
- 跨文件的同一人保持映射一致
- 首次替换时在当页脚注标注"原始信息已脱敏"
- 小组作业的脱敏范围扩展到：所有成员姓名、共同指导教师姓名（如有）

## 工作流程

### 第一阶段：初始设置

1. **获取原始文件**：读取用户提供的原始作业文件（docx/txt/pdf等）
2. **文件分类**：按上述分类器确定处理管线
3. **选择处理模式**：与用户确认全量覆盖/精选深度/混合批次
4. **个人信息脱敏**：按脱敏规则执行（单人/小组差异处理）

### 第二阶段：分析与初稿

1. **分析笔记**：对原作业做结构拆解、优缺点分析、可拓展方向识别。
   - 分析笔记不少于800字
   - 包含：结构分析、论证质量评估、引用核查、修改方向
2. **确定版本方向**：每份作业产出两个方向的版本
3. **编写修改意见**：明确本轮修改方向和具体改动
4. **生成新作品**：按修改意见产出实际内容，新作品不少于1500字
5. **可视化判断**：在分析笔记末尾评估是否适合生成图表
6. **编写修改过程**：记录从上一版到本版的变化

### 第三阶段：迭代深化

每轮迭代的深化方向由质量锚点指导，而非固定模板。

迭代原则：
- 每轮修改意见指向下一轮的修改方向
- 每轮修改过程记录从上一轮到本轮的变化
- 所有旧版本 **不删除、不覆盖**

### 第四阶段：收尾

1. **图表生成**：仅当可视化建议判断为"适合"时生成
2. **对照注**：撰写对照反思，对比当年的自己与今天的自己
3. **路径说明**：记录过程中遇到的技术问题和解决方案

## 编码注意事项

⚠️ **经验教训**（基于实际运行验证）：

1. **Python中文处理**：任何含中文、换行、特殊字符的Python代码，一律写 `.py` 文件执行，不在 `-c` 参数中内联
2. **文件写入**：优先使用 `Set-Content` 配合 `@'\''@` 块，而非 `open().write()`
3. **沙箱路径测试**：向不熟悉的路径写入前，先对单个文件做最小写入测试；避免目录名以数字+连字符开头
4. **raw string转义**：`r"\d"` 匹配数字，`r"\\d"` 匹配字面反斜杠+字母d
5. **中文引号**：python -c 参数中嵌入中文引号会与Shell字符串界定冲突，应全部规避

4. 版本质量锚点表
5. 处理模式选择说明
6. 交流风格规范
7. 文件命名与版本管理规则
